04 · 复现路径

运行、验证与重现实验

下面的命令从公开样例开始，完整覆盖编译、运行与独立验证。

快速开始

克隆、编译、运行、验证。

调度结果写入标准输出，可选阶段轨迹只写入标准错误，因此诊断不会污染分配格式。

克隆并编译

git clone https://github.com/rudykon/FPTR_Scheduler.git
cd FPTR_Scheduler

g++ -std=c++17 -O2 \
  src/scheduler.cpp src/core.cpp \
  -o scheduler

运行公开样例

mkdir -p /tmp/fptr-samples /tmp/fptr-output
cp space/data/cases/small-balanced.in \
  /tmp/fptr-samples/small-balanced.in
./scheduler \
  --stage full \
  --budget-ms 87 \
  --trace \
  < /tmp/fptr-samples/small-balanced.in \
  > /tmp/fptr-output/small-balanced.out

独立验证

python3 tools/scheduler_validator.py \
  --samples /tmp/fptr-samples \
  --output-dir /tmp/fptr-output
运行快速实验 
python3 experiments/paper_experiments.py \
  --quick \
  --out /tmp/fptr-quick-results

审计边界

每个结果都落到一次启动、一个实例和一次独立校验。

一次 launch 是拥有独立输入流、执行顺序、随机种子和墙钟测量的子进程。质量以每实例五次运行的中位数为单位，置信区间使用 5,000 次分层 bootstrap。

01

独立启动

固定实例、配置、随机种子与预算。

02

序列化输出

分配写入 stdout，阶段轨迹只写入 stderr。

03

独立验证与重算

重新解析结果、检查全部约束并重算传输量。

04

统一计分与哈希

迟到、非法或异常退出计零分；SHA-256 绑定工件。

仓库地图

实现、验证器、实验编排与图件生成各自独立。

仓库结构把调度器、独立验证、实验协议和网页图件分开，便于逐层检查模型契约与结论来源。

src/ — C++17 调度器、共享模型与阶段入口
tools/ — 独立解析、可行性验证与目标值重算
experiments/ — 确定性实例、实验编排、分析与绘图
tests/ — 模型契约与端到端回归测试
docs/ — GitHub Pages、浏览器 Demo 与静态双语内容
