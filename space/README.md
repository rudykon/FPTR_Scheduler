# FPTR Joint Beam and Resource Scheduler

This free Static Space executes the repository's real single-threaded C++17
scheduler in the visitor's browser through WebAssembly. Results are produced when
**Run real C++ scheduler** is clicked: the demo does not load precomputed scores and
does not reimplement or approximate FPTR in JavaScript. The scheduler and browser
bridge are synchronized with source commit
[`dca2f771`](https://github.com/rudykon/FPTR_Scheduler/commit/dca2f77141c2abd8a4741b229bb9c5f3053792ec).

Choose one of five deterministic public inputs or load a compatible local `.in`
file, then select one of five deadline budgets and six pipeline stopping points.
Each run exposes:

- cumulative `Base → Global → CG → Remask → Full` incumbent gains;
- the final user–resource allocation and legal multi-user sharing;
- the selected per-subband beam masks;
- per-user delivered and unmet traffic;
- the scheduler's unmodified stdout and stage trace;
- an independently recomputed score plus input, allocation, beam-budget, sharing,
  subband, trace-monotonicity, and score-consistency checks;
- a separately executed BeamFirst reference under the same selected budget;
- a downloadable JSON run record containing the input, allocation, raw outputs,
  validation evidence, timings, hash, and source provenance.

Custom inputs stay inside the local browser and are never uploaded to a demo
server. Because the deadline is enforced during real execution, exact scores and
timings can vary with browser and device speed. The included presets are synthetic
inputs generated by the public experiment harness; they explain algorithm behavior
and do not represent live base-station traffic.

To regenerate the presets, compile the checked-in C++ source with Emscripten, run
the WebAssembly smoke test, and serve the demo locally:

```bash
python3 space/generate_demo_cases.py
bash space/build_wasm.sh
node space/tests/smoke_wasm.js
python3 -m http.server --directory space 8000
```
